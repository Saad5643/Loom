Why Loom

Most of what you do online is a chain of small jobs. Open a tab, search, compare a few results, copy what you need, close the tab, repeat.

Loom hands that chain to an assistant that sits beside the page. It can read what's in front of you, so you ask about it in plain words. Give it a task and it works in the same window, one visible step at a time.

You choose the model it runs on. The build shown here uses qwen3:8b, and you can switch from the menu at the top of the panel.

01What is Loom?+

A desktop browser with an AI assistant built into a side panel. It reads the page you're on and can carry out tasks on the web in the same window.

02What can the Assistant do?+

Answer questions about the current page, and run tasks such as searching, comparing results, or pulling the ingredients out of a recipe. You see each step in the panel while it runs.

03Which model does it use?+

The panel shows the model it's using, qwen3:8b in this build. Open the menu next to the model's name to switch.

04Can I change the new tab page?+

Yes. Pin your own shortcuts, set the name in the greeting, choose light or dark, and pick the background from Customize.

05Can I use more than one profile?+

Yes. Switch profiles from the menu in the top-left corner of the window.

06Which systems does it run on?+

Windows.

Loom is engineered so your active web pages and keystrokes are never phoned home to train centralized frontier models.

Telemetry StatusZERO TRACKING

Built to read what is in front of you without sending it elsewhere.

Because Loom pairs browsing directly with an AI assistant that reads pages in real time, our architectural default is local execution. Here is exactly what stays on your computer and what touches an external network.

Browsing Data
Your search history, cookies, cached tabs, and profile settings are stored strictly in local application storage on your Windows installation. Loom does not operate cloud sync servers for browsing history.
Assistant & Page Context
When you ask a question about an active tab, the DOM text content is passed to the active inference runtime (qwen3:8b via local runtime). Page content is purged from working memory once the thread session closes.
Third-Party Models
If you select external cloud endpoints (OpenAI, Anthropic, or custom API keys), prompts and extracted page snippets will travel directly to that provider under your own key and credentials.
Telemetry & Updates
Loom checks for new version updates via GitHub Releases. No hardware identifiers, URLs, or query strings are attached to version check pings.
Contact & Inquiries
For privacy audits or security disclosures: privacy@loom.example
